## Handoff between producers and callers

- P3 writes a single-run JSON receipt to stdout. Core fields are `run_id`, `fixture_revision`, `conditions`, `configuration`, `metric`, `execution`, `validity`, `direction`, `input_bytes`, `output_bytes`, `roundtrip_ok`, `fixture_sha256`, `dictionary_sha256` (null for plain), `zlib_version` and `elapsed_ms`. Conditions, configuration and metric match the publish body. P2's `python -m adapters.seed --out receipts/producer.json` invokes the runner for the three calibration jobs, writes the artifact shapes and publishes using A's token. Accept optional `--promising-expires-at` with a UTC timestamp for the expiry scenario. Its JSON output gives named refs `promising`, `negative`, `distractor` and the three receipts. The seed process exits before B starts.
- P4 starts the platform service with fresh project IDs and token mappings for all rehearsal scenarios, seeds through P2, polls search for the required current versions, and launches P3's B command once per mode. For the semantic smoke check, P4 adds five synthetic completed observations on unrelated fixtures through the API. Use a new project for the scheduled expiry scenario. Confirm the promising result is searchable before its expiry. Then run B after the deadline while the other calibration records are still active. P4 uses P3's B calibration receipt to build the correction payload and uses the maintainer token for that call. Wait for the replacement version to appear in Atlas search for the corrected mode and record that B rejected its cohort. P4 logs request, catalog, budget, mode receipts and assertion outcomes to `receipts/rehearsal/`. Keep test credentials in local environment and exclude them from output. P1 provides the local env setup and the preflight.
